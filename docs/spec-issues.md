# 規格問題與原型的決定（給小組確認）

原型以 pytest-bdd 執行 `spec/features/` 的 452 個例子時，找到幾個規格本身互相矛盾的地方；另外有幾處規格沒有寫到、原型先做了決定。請小組逐項確認，確認後同步修改 `docs/` 與 `spec/features/`。

## A. 規格例子互相衝突（4 個例子，測試標為預期失敗）

| # | 位置 | 衝突 | 原型的做法 | 建議 |
|---|---|---|---|---|
| A1 | `執行排程發佈.feature`「Threads 帳號已被移除，排程時只發佈到其餘平台帳號」 | Background 的 P1 也在 12:00 到期、目標含 Threads；例子在 12:05 執行排程發佈，卻預期 Threads「收到 0 則」 | 依 Background 執行：P1 會發到 Threads | 例子改為只檢查 P3 的發佈紀錄，或 Background 的 P1 改成其他時間 |
| A2 | `重新連結平台帳號.feature`「Instagram 重新授權失敗」 | 同一組已過期的 Instagram 資料，此例預期授權狀態「有效」，「識別碼不一致」「名稱重複」兩例預期「失效」 | 依 BR-09「到期即失效」 | 此例的預期改為「失效」（表示資料沒有被改動） |
| A3、A4 | `修改貼文.feature` 的「修改已排程的貼文」「修改已排程貼文的內容」 | Background 的 P3 是「已排程但沒有任何目標」，BR-07 不允許這種狀態；依 BR-24 修改已排程貼文會檢查 BR-07，因此回 `NO_TARGET` | 依 BR-24 檢查 | Background 為 P3 加上目標平台帳號與待發佈紀錄 |

## B. 規格沒有寫到、原型先做的決定

| # | 主題 | 原型的做法 | 理由 |
|---|---|---|---|
| B1 | 平台授權導回的結果 | 平台連不上時回 `VERIFICATION_UNAVAILABLE`（不是 `PLATFORM_AUTH_FAILED`）；重新連結成功為 `relinked`、識別碼不一致為 `PLATFORM_ID_MISMATCH` | 需求 4.5.2 區分「暫時無法驗證」與「授權失敗」 |
| B2 | 重新連結沒有平台識別碼的帳號 | 一律視為識別碼不一致而拒絕 | 無法確認是同一個帳號時寧可拒絕（BR-38） |
| B3 | 圖片網址不是公開 https | 目標含 Threads 或 Instagram 時，排程或發佈當下回 `422 IMAGE_URL_NOT_PUBLIC` | 這兩個平台由平台下載圖片，不要等到發文才失敗 |
| B4 | 圖片像素上限 | 超過 5,000 萬像素回 `422 IMAGE_DIMENSION_INVALID` | 4.3.1 的寬高限制尚待查證；像素過多會在解碼時耗盡記憶體 |
| B5 | 手機照片的方向 | 依 EXIF 轉正後才計算寬高與裁切 | 否則直拍照片會被裁成橫的 |
| B6 | 連續登入失敗鎖定 | 鎖定時失敗次數歸零，到期後重新有 5 次機會 | 4.1 只寫「登入成功或解除鎖定時歸零」；照字面做的話，到期後輸錯一次又鎖 15 分鐘 |
| B7 | 排程發佈完成後的排程時間 | 保留（只有立即發佈已排程貼文時清空，BR-29） | 列表仍可看出原本排在何時 |
| B8 | 重試被拒絕的說明 | `NOTHING_TO_RETRY` 的 `detail.hints` 為 `[{platform_account_id, account_name, reason}]`，`reason` 沿用稽核的跳過原因 | API 設計只寫了 `detail.hints`，沒有格式 |
| B9 | 逾時恢復的稽核 | 沒有自動重送時補一筆系統的「發佈貼文」；有自動重送時寫一筆「自動重試發佈」，原因代碼 `PLATFORM_CONFIRMED_NOT_PUBLISHED` | 規格待確認事項 §5 #2 尚未決定 |
| B10 | 「誰正在處理這一筆」的租約長度 | 270 秒（單筆總時限 180 秒＋發文與確認各一次呼叫＋餘裕），不是 D-01 的 3 分鐘 | 發文與確認可能在 180 秒時限之後才結束 |
| B11 | 正式環境的圖片儲存 | Neon Object Storage（S3 相容、公開讀取的 bucket）；PostgreSQL 的 `media_blob` 保留為備案（2026-11-22 決定，不用 Cloudflare R2） | R2 開通需要信用卡；Neon 免費 5 GB |
| B12 | 修改已排程貼文 | 依 BR-24 完整檢查發佈限制，包含目標的授權狀態 | 規格條文如此；授權在排程後過期時，要先處理目標才能改文字 |
| B13 | Instagram 的授權方式 | 改用 Facebook 企業版登入（foundation-plan D-05 更新）；Token 預設不過期，授權到期時間為空 | 新建立的 Meta App 已經不能用 Instagram Login |
| B14 | 一次授權分享多個 Instagram 帳號 | 拒絕（`PLATFORM_AUTH_FAILED`），請只分享一個 | 一次連結對應一個平台帳號；不猜要用哪一個 |
| B15 | 比例已符合、但 Instagram 讀不了的原圖 | MPO 或帶 EXIF 旋轉的照片，另存一份重新編碼、轉正的 Instagram 版本；寬高相同，不算裁切。重新編碼後超過 8 MB 時退回用原圖（不讓只發其他平台的貼文無法附圖） | Instagram 官方不接受 MPO；BR-06 的「與原圖相同」解讀為畫面相同 |
