# P0 後端收尾：登出、幹部帳號、修改與刪除貼文 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 補齊前端畫面需要、但後端還沒有的 P0 端點：登出、管理員查看／建立／停用／啟用幹部帳號、修改與刪除貼文。

**Architecture:** M1 在 `app/m1_accounts` 加 `/auth/logout` 與 `/users`；M3 在 `app/m3_posts` 加 `PATCH`、`DELETE /posts/{id}`。刪除已排程貼文時由 M4 的 `lifecycle.on_post_deleting` 把待發佈紀錄改為已取消（《API 設計》18～21、architecture 的跨模組呼叫）。所有改變貼文的操作先鎖定貼文，與排程認領互斥。

**Tech Stack:** Python 3.12、FastAPI、SQLAlchemy 2、PostgreSQL 17、pytest。

**Spec:** `docs/api-design.md` §3.1（3、6、7、9）與 §3.3（20、21）、`docs/requirements.md`（4.1、BR-11、BR-13、BR-17～BR-21、BR-27、BR-35、BR-40）、`spec/features/` 的 `登出`、`查看幹部帳號`、`建立幹部帳號`、`停用帳號`、`啟用帳號`、`修改貼文`、`刪除貼文`。

## Global Constraints

- 使用者看得到的文字用繁體中文；欄位格式錯誤一律 `400 VALIDATION_ERROR`。
- Email 一律標準化（去前後空白、轉小寫）後比對與儲存（BR-40）；初始密碼少於 8 字元或空白 → `422 PASSWORD_TOO_SHORT`。
- 密碼只存雜湊；任何回應與 Log 都不含密碼或雜湊。
- 系統至少保留一位啟用中的管理員（BR-19）；停用帳號同時撤銷該帳號所有 session。
- 只有草稿與已排程貼文可以修改或刪除（BR-13）；刪除是軟刪除，發佈紀錄、變更歷程、稽核保留（BR-35）。
- 不新增套件；ruff line-length 110。

## Review Focus

1. 兩位管理員同時停用對方：結果仍至少有一位啟用中的管理員（Task 1，`test_last_active_admin_check_locks_admin_rows` 以鎖定順序驗證；並在程式中鎖定全部啟用中的管理員）。
2. 同一個 Email 幾乎同時建立兩次：第二次是 `409 EMAIL_TAKEN`，不是 500（Task 1，`test_duplicate_email_from_database_constraint_is_409`）。
3. 排程時間到的同時刪除或修改已排程貼文：不是被刪除／修改，就是已進入發佈中而回 409，不會發出已刪除的貼文（Task 2，`test_deleted_scheduled_post_is_not_published`）。
4. 登出後拿舊的 Access Token 呼叫任何端點 → 401（Task 1，`test_logout_revokes_only_current_session`）。
5. 被停用的人手上的 Token 立刻失效（Task 1，`test_disable_revokes_sessions_and_blocks_login`）。

### Task 1: 登出與幹部帳號

**Files:** Modify `app/m1_accounts/{router,service,schemas,repository}.py`；Test `tests/api/test_users.py`。

**Interfaces:**
- `POST /api/v1/auth/logout` → 204：撤銷目前 session、清除 refresh Cookie、稽核 `LOGOUT`。
- `GET /api/v1/users`（管理員）→ `{"items": [{id, email, name, role, status, locked_until, is_locked}]}`，依 id 排序，含停用帳號。
- `POST /api/v1/users`（管理員）`{email, name, role, initial_password}` → 201 同上格式；稽核 `USER_CREATE`（target `user_account`）。
- `PUT /api/v1/users/{id}/status`（管理員）`{"status": "disabled" | "active"}` → 200 同上格式；`409 USER_ALREADY_DISABLED`、`409 USER_NOT_DISABLED`、`409 LAST_ACTIVE_ADMIN`；稽核 `USER_DISABLE`／`USER_ENABLE`。

### Task 2: 修改與刪除貼文

**Files:** Modify `app/m3_posts/{router,service,repository,schemas}.py`；Create `app/m4_scheduling/lifecycle.py`；Test `tests/api/test_post_editing.py`。

**Interfaces:**
- `PATCH /api/v1/posts/{id}` `{"content": str}` → 200 `PostOut`。撰稿者只能改自己的（403）；不是草稿或已排程 → `409 POST_NOT_EDITABLE`；空白 → `422 CONTENT_EMPTY`；已排程貼文以新內容檢查發佈限制（`422 CONTENT_TOO_LONG`），狀態與排程時間不變。
- `DELETE /api/v1/posts/{id}` → 204。同樣的權限與狀態檢查；設定 `deleted_at`；已排程時呼叫 `lifecycle.on_post_deleting(db, post, actor)`：待發佈紀錄改為已取消（歷程 `POST_DELETED`）。之後 `GET /posts/{id}` 404、列表不顯示、`GET /posts/{id}/publish-records` 仍可查（`post_deleted: true`）。
- `m4_scheduling.lifecycle.on_post_deleting(db: Session, post: Post, actor: UserAccount) -> None`。
