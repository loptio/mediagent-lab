# Threads Linking and Publishing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin links a Threads account through Meta's OAuth window, and a post published to that account really appears on Threads, with the permalink stored in the publish record.

**Architecture:** OAuth is a second capability next to publishing: adapters that support it implement `OAuthProvider` (`authorization_url`, `exchange_code`). M2 exposes the two endpoints of `docs/api-design.md` #12–13; the callback is authenticated only by a signed, short-lived `state`. `ThreadsAdapter` implements the three-step contract against `graph.threads.com` (container → status → publish). A Caddy container (compose profile `oauth`) gives the local stack an HTTPS origin for the OAuth redirect.

**Tech Stack:** as stage 1 (FastAPI, SQLAlchemy, httpx, PyJWT); Caddy 2 for local HTTPS.

**Spec:** `docs/foundation-plan.md` D-01, D-05, D-11, D-13; `docs/api-design.md` §3.2 (#12, #13); `docs/requirements.md` 4.2, BR-37, BR-38, NFR-02, NFR-06; `docs/architecture.md` §7.2, §11.

## Global Constraints

- Scopes requested: exactly `threads_basic` and `threads_content_publish` (NFR-06).
- Hosts: authorization window `https://threads.com/oauth/authorize`; API `https://graph.threads.com`; API version path `/v1.0`.
- Access tokens, the app secret and authorization codes never appear in API responses, logs, `platform_error_message`, `platform_auth_event`, or redirect URLs produced by us.
- The stored credential is MultiFernet-encrypted JSON: `{"account_name", "access_token", "user_id", "username"}`.
- `state` is a JWT signed with `OAUTH_STATE_SECRET` (falls back to `JWT_SECRET`), valid 10 minutes, carrying admin id, platform and mode.
- Retry rules (D-11): `begin` and `check` retry on HTTP 429/5xx at most 2 times; `finalize` retries only on 429; timeouts and unknown outcomes are never retried.
- Automated tests never call Meta: `httpx.MockTransport` or `MockAdapter` only.
- Relinking (BR-38) and Instagram are out of scope; requests for them get a clear 400.

## Review Focus

1. The user denies the authorization, or Meta returns an error on the redirect: no account is created, a `LINK_FAILED / PLATFORM_AUTH_FAILED` event is recorded, and the browser lands on a page that says so (Task 1, `test_callback_when_user_denies_records_auth_event`).
2. A forged, tampered or expired `state`: rejected without calling the platform and without creating anything (Task 1, `test_callback_rejects_tampered_or_expired_state`).
3. `THREADS_APP_ID` / `THREADS_APP_SECRET` not configured: starting OAuth fails with a clear message instead of sending the admin to a broken Meta page (Task 2, `test_authorization_requires_app_configuration`).
4. The access token expires or is revoked between linking and publishing: the record is `FAILED / AUTH_INVALID`, the account becomes invalid, nothing is retried (Task 2, `test_invalid_token_is_auth_invalid`).
5. `finalize` gets no answer although Threads did publish: the engine checks the container once and records success instead of a timeout that would invite a duplicate retry (Task 2, `test_finalize_reported_as_timeout_is_checked_once`).

### Task 2: Threads adapter

**Files:** Create `app/m2_platforms/adapters/threads.py`, `tests/unit/test_threads_adapter.py`. Modify `app/m5_publishing/engine.py`, `app/main.py`, `tests/api/test_publish_engine.py`, `tests/api/test_link_oauth.py`.

**Interfaces — Produces:** `ThreadsAdapter(transport: httpx.AsyncBaseTransport | None = None, retry_delay: float = 1.0)` implementing `PlatformAdapter` and `OAuthProvider`.

Requests (all against `https://graph.threads.com`, token as form field on POST and query parameter on GET):
- `authorization_url`: `https://threads.com/oauth/authorize?client_id&redirect_uri&scope=threads_basic,threads_content_publish&response_type=code&state`; raises `OAuthFailed` when app id or secret is not configured.
- `exchange_code`: `POST /oauth/access_token` (form: `client_id`, `client_secret`, `grant_type=authorization_code`, `redirect_uri`, `code`) → `access_token`, `user_id`; `GET /access_token?grant_type=th_exchange_token&client_secret&access_token` → long-lived `access_token`, `expires_in`; `GET /v1.0/me?fields=id,username`. Any 4xx → `OAuthFailed`; network error or 5xx → `VerificationUnavailable`.
- `begin`: `POST /v1.0/{user_id}/threads` (form: `media_type=TEXT`, `text`, `access_token`) → `Started(id)`.
- `check`: `GET /v1.0/{container_id}?fields=status,error_message` → `FINISHED`→`READY`, `IN_PROGRESS`→`PROCESSING`, `PUBLISHED`→`PUBLISHED`, `ERROR`→`FAILED(CONTENT_REJECTED)`, `EXPIRED`→`FAILED(OTHER)`; no `request_ref`, or any error → `UNKNOWN`.
- `finalize`: `POST /v1.0/{user_id}/threads_publish` (form: `creation_id`, `access_token`) → media id; then `GET /v1.0/{media_id}?fields=id,permalink`; a failed permalink lookup still returns `Published` with `post_url=None`.
- Failure mapping: HTTP 401, Graph error code 190, or a message mentioning the access token → `AUTH_INVALID`; 429 or 5xx → `PLATFORM_UNAVAILABLE`; other 4xx → `CONTENT_REJECTED`; connection error → `PLATFORM_UNAVAILABLE`; no response to `finalize` → `TIMEOUT`. Messages are scrubbed of the token and app secret and cut to 300 characters.
- `count_chars`: one per character, except emoji, which count as their UTF-8 byte length (Threads documentation; to be confirmed against the live API).

Engine change: when `finalize` returns `Failed(TIMEOUT)`, do the same single `check` already done for an asyncio timeout.
